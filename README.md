# Каталог товаров

Администратор добавляет товар через Telegram-бота: отправляет фотографию с названием в подписи. Фотография хранится в MinIO, запись о товаре — в PostgreSQL. Каталог на Next.js App Router открывается в браузере и Telegram Mini App. API написан на FastAPI, бот — на aiogram 3.

## Запуск

Нужен Docker Compose v2+. Из корня проекта:

```sh
cp .env.example .env
```

Заменить пароли в `.env`, затем запустить:

```sh
docker compose up -d --build
```

Каталог доступен по адресу http://localhost:8080. Изначально товаров нет. MinIO собирается из закреплённого исходного релиза; первая сборка занимает больше времени.

## Настройка бота

Заполнить в `.env`:

- `BOT_TOKEN` — токен бота;
- `ADMIN_IDS` — числовые Telegram ID администраторов через запятую;
- `PUBLIC_URL` — внешний HTTPS-адрес каталога;
- `WEBHOOK_SECRET` — случайные 64 hex-символа; получить значение можно командой `openssl rand -hex 32`.

Внешний HTTPS-прокси должен направлять запросы на локальный порт 8080.

```sh
docker compose --profile telegram up -d --build --scale api=2 --scale web=2 --scale bot=2
docker compose --profile telegram run --rm --no-deps bot python manage.py webhook
```

Вторая команда регистрирует webhook. При обычном перезапуске повторять её не нужно.

В личном чате с ботом:

1. Отправить `/start` и открыть каталог кнопкой.
2. С аккаунта администратора отправить `/create`, затем одно фото с названием в подписи.
3. Проверить появление товара в каталоге. Попытка добавления с другого аккаунта должна завершиться отказом.

Название ограничено 255 символами, фотография — 5 МиБ. Альбомы не поддерживаются. Администратор также может сразу отправить фото с подписью, без `/create`.

## Тесты

Для backend нужны Python 3.12 и виртуальное окружение. Из каталога `backend`:

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q tests/test_unit.py
```

Эти тесты не требуют PostgreSQL, MinIO или доступа к Telegram. Они проверяют ограничения фотографии, валидацию webhook, обработку ошибок хранилища и закрытие соединения.

Для интеграционных тестов запустить из корня проекта:

```sh
docker compose --env-file .env.example -f compose.yaml -f compose.test.yaml up -d db minio
```

Задать переменные окружения процесса pytest:

```text
TEST_DATABASE_URL=postgresql://catalog:replace-with-a-local-password@127.0.0.1:15432/catalog
TEST_S3_ENDPOINT=127.0.0.1:19000
S3_ACCESS_KEY=catalog
S3_SECRET_KEY=replace-with-another-local-password
```

Если стенд уже создавался с другими паролями, использовать их. Затем из `backend`:

```sh
python -m pytest -q
```

Без переменных тестового стенда интеграционные проверки пропускаются. Тесты создают отдельные схемы и bucket, после выполнения удаляют только их. Telegram заменён `FakeBot`; используется тот же обработчик заданий, что и в приложении.

Проверка frontend из каталога `frontend`:

```sh
npm ci
npm run check
npm run build
```

## Устройство

- SQL-запросы выполняются через asyncpg с параметрами. В базе две таблицы: товары и задания.
- Webhook отвечает 200 после записи update в PostgreSQL. Уникальность `(kind, update_id)` отсекает повторную доставку. Обработчики выбирают задания через `FOR UPDATE SKIP LOCKED`; изменение товара, постановка ответа и завершение update выполняются в одной транзакции.
- API, бот и Next.js не хранят пользовательское состояние в процессе или файлах. Фото записывается по постоянному ключу из bot/chat/message ID, поэтому повтор обработки не создаёт второй товар.
- Каталог публичный. Право добавлять товары проверяется ботом по Telegram ID отправителя.
- API читает фотографию перед отправкой HTTP-заголовков. Сетевой сбой хранилища возвращает 503; буфер ограничен 5 МиБ на запрос.

## Ограничения

Compose рассчитан на один хост. PostgreSQL, MinIO и nginx запускаются в одном экземпляре; несколько реплик приложения не обеспечивают отказоустойчивость всей инфраструктуры. В локальном стенде используются root-ключи MinIO.

Если Telegram принял ответ, а процесс завершился до COMMIT, сообщение может прийти повторно. После пяти ошибок задание остаётся в БД для разбора:

```sql
SELECT id, kind, error FROM jobs WHERE NOT done AND attempts >= 5;
```

История дедупликации не очищается автоматически. После окончательной ошибки обработки может остаться неиспользуемый объект S3.

Работа с реальным Telegram, внешний HTTPS и отображение на телефоне и компьютере пока не проверены.
